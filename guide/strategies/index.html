Creating custom strategies

The pydecoys.strategies module exposes the API used for decoy strategies.

The basic type signature all strategies must follow is strategies.DecoyGenerator. This is as simple type alias:

1from typing import Callable
2
3type SeqLike = 'str | Seq | MutableSeq'
4type DecoyGenerator[T: SeqLike] = Callable[[T], T]

Note that strategies.SeqLike is a Union type of str, Seq and MutableSeq, but it doesn’t actually require Biopython.

Creating a simple strategy

To illustrate how to create custom strategies, let’s create a naïve randomizer. It takes a target protein and returns a fully random decoy protein of same length. We can use PyDecoy’s own RNG strategies.RAND. We can also use PyDecoy’s strategies.STD_AMINOACIDS to pool from. This is a str containing the 20 standard aminoacid single-letter codes.

 1# Use PyDecoys own RNG or another RNG with a fixed seed to ensure
 2# reproducibility
 3from pydecoys.strategies import RAND
 4
 5# PyDecoys also has a str containing all 20 standard aminoacid
 6# single-letter codes
 7from pydecoys.strategies import STD_AMINOACIDS
 8
 9def random(sequence: str) -> str:
10    length = len(sequence)
11    new = RAND.choices(STD_AMINOACIDS, k=length)
12    return "".join(new)

This will work perfectly already, and for most usecases it’ll be enough. However, it’ll fire static type checkers: random doesn’t yet implement the correct type signature we saw earlier.

Also, our implementation isn’t interfaceable with Biopython, which means it might break (or at least return a str) when it should return Seq or MutableSeq.

Fixing these problems is easy:

1from pydecoys.strategies import RAND, STD_AMINOACIDS, SeqLike, seq_cast
2
3def random[T: SeqLike](sequence: T) -> T:
4    length = len(sequence)
5    new = RAND.choices(STD_AMINOACIDS, k=length)
6    # `seq_cast` handles casting the return value to `sequence`'s type
7    return seq_cast(sequence, "".join(new))

Note that strategies.SeqLike and strategies.seq_cast() work without Biopython installed. Although this function correctly interfaces with Biopython, it doesn’t need Biopython to work!

Strategies with state

In the previous example, we implemented a naïve randomizer. In practice, a much more useful strategy is to give each aminoacid a weighted likelihood based on the proportions of aminoacis from the target database. For this, the generator would need some way of gathering context from the database prior to decoy generation.

PyDecoys has a specific protocol for that: strategies.ContextfulGenerator. When a function that takes a set of targets receives a strategies.ContextfulGenerator as strategy, it can pass all of the set database to it beforehand.

We need a strategies.DecoyGenerator, so we’ll override its __call__ method. We also need to implement the strategies.ContextfulGenerator.learn_context() and strategies.ContextfulGenerator.reset() methods, and add a strategies.ContextfulGenerator.is_set attribute.

Instead of using strategies.STD_AMINOACIDS, let’s use strategies.EXT_AMINOACIDS. This str includes pyrrolysine (Pyl, O) and selenocysteine (Sec, U). It also includes the B (aspartic acid or asparagine), J (leucine or isoleucine), Z (glutamic acid or glutamine) and X (any aminoacid) codes. Since we’ll weight each aminoacid based on its proportion on the target dataset, those aminoacids will only show up if they are included in the target dataset already.

 1from typing import Iterable
 2
 3from pydecoys.strategies import (
 4    RAND,
 5    EXT_AMINOACIDS,
 6    SeqLike,
 7    seq_cast,
 8)
 9
10# Since `ContextfulGenerator` is a protocol, no need to inherit it
11class SmartRandomizer:
12    def __init__(self):
13        # `None` placeholder until contextualization
14        self._weights = None
15
16    def learn_context(self, sequences: Iterable[SeqLike]) -> None:
17        # We init weights
18        self._weights = [0] * len(EXT_AMINOACIDS)
19
20        for seq in sequences:
21            for aa in seq:
22                # The position of each weight must overlap with its aminoacid
23                # pos
24                pos = EXT_AMINOACIDS.find(aa)
25                self._weights[pos] += 1
26
27    def reset(self):
28        self._weights = None
29
30    @property
31    def is_set(self) -> bool:
32        # We can use a property to ensure is_set is always updated
33        return self._weights is not None
34
35    def __call__[T: SeqLike](self, sequence: T) -> T:
36        length = len(sequence)
37        new = RAND.choices(EXT_AMINOACIDS, weights=self._weights, k=length)
38        return seq_cast(sequence, "".join(new))

This gets us a working decoy strategy that correctly implements weights before running! When calling pydecoys IO or Iterable functions, it’ll automatically pass the database to the instance if it’s unset, and reset it again at the end.

Warning

When using IO or Iterable functions from PyDecoys with an unset context-dependant strategy, the API will handle setting it, generating the decoys and then resetting it at the end. For single-data functions, using an unset strategy will raise a ValueError, since they never receive a full dataset. See pydecoys.get_contextualized_strategy() to circumvent this.

Adding new enzymes

The strategies.ReversePep, strategies.ShufflePep and strategies.RandomizePep classes allow you to set new enzyme specifications for reversepep, shufflepep and randomizepep strategies. Setting new enzymes is an easy method call. Let’s set high-specificity chymotrypsin for reversepep:

1import pydecoys
2from pydecoys.strategies import ReversePep
3
4reversepep_chymohs = \
5    ReversePep.from_enzyme('FWY', nocut='P', nocut_n=None, sense='C')
6
7pydecoys.register('reversepep-chymohs', reversepep_chymohs)

Breaking up each paremeter, cut specifies which aminoacids the enzyme cuts at, nocut specifies aminoacids that stop cleavage when at the C-terminal bond of cut, nocut_n specifies aminoacids that stop cleavage when at the N-terminal bond of cut, and sense specifies the cleavage sense.

That’s it. Now you can use a reversepep strategy with high specificity chymotrypsin by providing 'reversepep-chymohs' or reversepep_chymohs as a strategy.

Enzyme-specific strategies

You might want to set your own enzyme-specific strategy. Luckily, there’s an ABC for that: strategies.EnzymeSpecificGenerator. This class sets up the strategies.EnzymeSpecificGenerator.from_enzyme() method we used earlier to add the new enzyme.

Most importantly, it sets the strategies.EnzymeSpecificGenerator.split_sequence() method. This method splits a given sequence into its enzymatic fragments (minus cleavage sites) and the cleavage sites themselves. It yields tuples of an enzymatic fragment and False or a cleavage site and True, in the order they appear in the sequence.

Let’s redo the naïve randomizer, but this time let’s randomize peptides:

 1from collections.abc import Sequence
 2
 3from pydecoys.strategies import (
 4    RAND,
 5    EXT_AMINOACIDS,
 6    SeqLike,
 7    seq_cast,
 8    EnzymeSpecificGenerator
 9)
10
11class RandomizePep(EnzymeSpecificGenerator):
12    def __call__[T: SeqLike](self, sequence: T) -> T:
13        decoy_list = []
14        for frag, cleavage in self.split_sequence(sequence):
15            if not cleavage:

17                new = RAND.choices(EXT_AMINOACIDS, k=length)
18                frag = "".join(new)
19            decoy_list.append(frag)
20
21        decoy = "".join(decoy_list)
22        return seq_cast(sequence, decoy)
23
24# We can now create pep randomizers:
25randompep_trypsin = RandomPep('KR', nocut='P', sense='C')

Keeping N- and C-termini

You might also want to preserve the N-, C- or both termini from the target protein in-place. To accomplish that, you can use one of the following factories: strategies.keepns(), strategies.keepsc() and strategies.keepsterm(). Each factory returns a new callable that preserves the terminal aminoacids from the argument callable.

 1from pydecoys.strategies import ContextfulGenerator, keepsn, keepsc
 2
 3# The `sequence` value is passed directly without the aminoacid that
 4# should be preserved. The aa is reinserted after the wrapped function
 5# returns.
 6random_keepn = keepsn(random)
 7
 8class DummyContextfulGenerator:
 9    def __init__(self):
10        self.is_set = False
11
12    def learn_context(self, sequences):
13        self.is_set = True
14
15    def reset(self):
16        self.is_set = False
17
18    def __call__(self, sequence):
19        return sequence
20
21dummy = keepsterm(DummyContextfulGenerator())
22assert isinstance(dummy, ContextfulGenerator)

Warning

Those factories cause the original strategies.DecoyGenerator to be blind to the terminals they preserve. For example, strategies.ContextfulGenerator objects will preserve their functionality, but will discard the aminoacids that shouldn’t be altered from each sequence when learning context.

If you need your decoy strategy to still see those aminoacids, you’ll need to implement this functionality.

Fusing targets and decoys

There’s also a factory to fuse the target and decoy sequences into one, prepending the target to the decoy: strategies.fuses(). You can use them as the other two:

1random_fuse = fuses(random)
2
3# Stacking them works as well
4random_keepn_fuse = fuses(keepsn(random))

If you wish to add a radical between the target and the decoy such that the result is target-radical-decoy, you can pass it to fuses():

1# Resulting sequences will be the target and decoy, joined by 'R'
2random_fuse = fuses(random, radical='R')

For example:

>>> random_fuse = fuses(random, radical='KRI')
>>> random_fuse('SINDHRRLSG')
'SINDHRRLSGKRINVGSKSREDI'
